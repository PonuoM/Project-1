**สำหรับหารือร่วมกันระหว่าง: เจ้าของโปรเจกต์, Claude (Integrator/Tools/PixelLab) และ Codex/Gemini (Art/Design)**
**วันที่:** 14 ต.ค. 2026

## 1. วิเคราะห์ต้นตอของปัญหา (ทำไมทำแบบปกติแล้วพัง?)

จากสัดส่วนจริงของ `design/pixellab/chibi-motion/hero-ref-64.png` (ตัวละครสูง ~50 art px ในกรอบ 64×64):
1. **สัดส่วนพื้นที่พิกเซล (Pixel Budget):**
   - **หัว + ผม:** สูง ~28 px (กินพื้นที่ ~56% ของตัวละคร)
   - **ลำตัว + แขน:** สูง ~13–14 px (แขนยาวแค่ ~11 px)
   - **กางเกง + รองเท้า:** เหลือพื้นที่รวมกันแค่ **~8–9 px** (ช่วงกางเกงเหนือรองเท้าบูทเห็นชัดจริงๆ แค่ 3–4 px!)
2. **ปัญหาถ้าให้ AI (PixelLab / MiniMax) เจนแยกชิ้นตรงๆ:**
   - AI วาดพิกเซลใหม่ทุกเฟรม ขอบของเสื้อและกางเกงที่เจนคนละรอบจะขยับเหลื่อมกัน 1–2 px ทำให้เห็นรอยแหว่งหรือเส้นขอบดำ `#2e1816` ซ้อนกันจนเป็นก้อนดำทึบ
   - ค่าเจนระเบิด (Combinatorial Explosion) ถ้าต้องเจนทุกชุดผสม × ทุกท่า
3. **ปัญหาถ้าตัดชิ้นส่วนหมุนแบบกระดูก 2D (Spine / Cutout Rotation):**
   - การหมุนภาพพิกเซลเล็กๆ (เช่น แขน 11 px หรือขาสั้นๆ) ทำให้ตารางพิกเซลบิดเบี้ยว (Mixels / ขอบแตก) ไม่คมเหมือนที่ PixelLab วาด

## 2. สถาปัตยกรรมที่แนะนำ: Hybrid Modular Pipeline (แบ่งชิ้นส่วนตามพฤติกรรมการขยับ)

แทนที่จะใช้วิธีเดียวกับทุกชิ้น ให้แบ่งอุปกรณ์สวมใส่ออกเป็น **3 ระบบย่อย** ตามธรรมชาติของ Chibi:

```text
[ระบบที่ 1: Rigid Socket Layers]  --> อาวุธ, หมวก, ทรงผม, หน้ากาก/แว่น (ภาพนิ่ง ไม่ต้องเจนอนิเมชั่น!)
[ระบบที่ 2: Deforming Body]       --> เสื้อ, ผ้าคลุม (ขยับตามท่าด้วย UV Map หรือ Skeleton-v3)
[ระบบที่ 3: Compact Lower Body]   --> กางเกง, รองเท้า (พื้นที่แค่ 8px ใช้ Template ขา + Palette/Mask)
```

## 3. รายละเอียดทั้ง 4 เทคนิคหลัก

### เทคนิคที่ 1: ระบบ Rigid Socket & Hair Sub-Layer (สำหรับ **หมวก, ทรงผม, อาวุธ**)
**หลักการ:** หัวของตัวละคร Chibi แทบไม่เคยบิดรูป (Deform) ในทุกท่า (เดิน, ฟัน, สกิล) หัวจะแค่ขยับตำแหน่ง `(x, y)` ขึ้น-ลง-ซ้าย-ขวา หรือก้ม/เงยเล็กน้อย

1. **การยึดจุด (Head Anchor Tracking):**
   - สกัดพิกัด `head_anchor (dx, dy)` (เทียบจากจุดอ้างอิงหัวในเฟรม `hero-ref-64.png`) ออกมาจากทุกเฟรมของอนิเมชั่นร่างกาย (`body-walk`, `body-slash`, `body-chop`)
   - สามารถหา `head_anchor` ได้แม่นยำระดับ 1 พิกเซลด้วยการทำ Template Matching (Cross-correlation) ของใบหน้า/ดวงตาเทียบกับเฟรมตั้งต้น (เพราะหน้าไม่เปลี่ยนรูป)
2. **การแยกชั้นทรงผมเพื่อไม่ให้ทะลุหมวก (MapleStory Hair-Culling Rule):**
   - ห้ามวาดทรงผมเป็นชิ้นเดียว ให้แบ่งสไปรต์ทรงผมเป็น 2 เลเยอร์:
     - `hair_front.png`: หน้าม้า + ปอยผมข้างแก้ม + ท้ายทอยด้านล่าง
     - `hair_top.png`: ผมช่วงกระหม่อมด้านบน/หางม้าสูง
   - กำหนด Tag ของหมวกแต่ละใบเป็น 3 ประเภท:
     - `hat_type = "none"` หรือ `"circlet"` (มงกุฎ/กิ๊บ/เขา): วาด `hair_front` + `hair_top` + `hat`
     - `hat_type = "cap"` (หมวกแม่มด/หมวกเกราะครึ่งหัว): ซ่อน `hair_top` อัตโนมัติ วาดเฉพาะ `hair_front` + `hat` (ทำให้หมวก 100 ใบใส่กับผม 100 ทรงได้โดยผมไม่ทะลุหมวก!)
     - `hat_type = "full_helm"` (หมวกเกราะคลุมทั้งหัว): ซ่อนทั้ง `hair_front` และ `hair_top`
3. **การผลิตชิ้นงาน (Codex/Gemini → Claude):**
   - Codex/Gemini เจน **แผ่นรวมหมวก 4×4** และ **แผ่นรวมทรงผม 4×4** บนพื้นเขียว `#00B140` (เหมือนแผ่นอาวุธ `weapons-g1b`)
   - Claude ใช้สคริปต์ตัดเป็น native sprite 64×64 แล้วประกอบเข้ากับทุกท่าได้ทันที **ต้นทุนการเจนอนิเมชั่น = 0 gen!**

### เทคนิคที่ 2: ระบบ UV Lookup Map / Pixel Remapping (สำหรับ **เสื้อ และ กางเกง** แบบไม่เสียค่าเจนซ้ำ)
**หลักการ:** แยก "การเคลื่อนไหว (Motion)" ออกจาก "ลวดลายชุด (Appearance)" โดยใช้แผนที่พิกัดสี `(R=U, G=V, B=PartID)`

1. **สร้าง Base UV Animation เพียงครั้งเดียวต่อ 1 ท่า:**
   - นำเฟรมอนิเมชั่นตัวละครพื้นฐานที่มีอยู่แล้ว (`body-walk`, `body-slash`, `body-chop`) มาทำแผ่น `uv_map` สำหรับแต่ละส่วน:
     - `PartID 1`: แขนหน้า (Front Arm)
     - `PartID 2`: ลำตัว/เสื้อ (Torso)
     - `PartID 3`: แขนหลัง (Back Arm)
     - `PartID 4`: ขาหน้า + ขาหลัง (Legs / Pants + Boots)
   - ในแต่ละพิกเซลของอนิเมชั่น บันทึกว่าพิกเซลนั้นตรงกับพิกัด `(u, v)` ใดของท่ายืน (`hero-ref-64.png`)
2. **เวลาเพิ่มเสื้อใหม่ หรือ กางเกงใหม่:**
   - ออกแบบเฉพาะ **ภาพนิ่งท่ายืน 1 เฟรม** (จาก Codex/Gemini หรือ `edit-image-pixen` เพียง 1 gen)
   - สคริปต์ของ Claude อ่านสีจากภาพนิ่งตามพิกัด `(u, v)` ไปวางลงในทุกเฟรมของทุกท่าโดยอัตโนมัติ แล้ววาดเส้นขอบนอก `#2e1816` รอบชิ้นส่วน
3. **ข้อดี & ข้อจำกัด:**
   - **ข้อดี:** เปลี่ยนเสื้อแยกกับกางเกงได้อิสระ 100%, พิกเซลไม่เหลื่อมกันเลย, ประหยัดค่าเจน PixelLab มหาศาล (ชุดใหม่ใช้แค่ภาพนิ่ง)
   - **ข้อจำกัด:** เหมาะกับเสื้อ/กางเกงที่แนบตัวหรือทรงใกล้เคียงตัวฐาน; ถ้าเป็นชุดที่มีชายผ้าคลุมยาวสะบัดตามแรงฟัน ต้องแยก "ผ้าคลุม (Cape)" ออกเป็นเลเยอร์ด้านหลังต่างหาก

### เทคนิคที่ 3: การแยกเลเยอร์ เสื้อ / แขนเสื้อหน้า / กางเกง ด้วย Z-Order ที่ถูกต้อง (กรณีใช้ PixelLab เจนอนิเมชั่น)
ปัญหาใหญ่ของตัวละครหันข้าง (Side-view Chibi) คือ **"แขนหน้า (Front Arm) ต้องทับลำตัว แต่ลำตัวต้องทับกางเกง"**

หากไม่แยกเลเยอร์แขนหน้าออกจากตัวเสื้อ เวลาเปลี่ยนเสื้อหรือถืออาวุธ แขนจะจมใต้เสื้อ หรือชายเสื้อจะแหว่ง

#### ลำดับการวาดเลเยอร์ (Z-Order จากหลังมาหน้า) ที่ต้องล็อกให้ตรงกันทั้งเกม:
| ลำดับ | ชื่อเลเยอร์ (Layer) | หมายเหตุ |
| :--- | :--- | :--- |
| **0 (หลังสุด)** | `back_cape` | ผ้าคลุมหลัง / ปีก / อาวุธสะพายหลัง |
| **1** | `weapon_behind` | อาวุธ (เฉพาะเฟรมที่ง้างไปด้านหลังหัว เช่น เฟรม windup ของ `chop2-sword`) |
| **2** | `back_arm` + `back_sleeve` | แขนข้างไกลลำตัว + แขนเสื้อข้างไกล |
| **3** | `legs_boots` | ขา + รองเท้า |
| **4** | `pants` | กางเกง / กระโปรง (วาดทับขอบบนของรองเท้า) |
| **5** | `torso_shirt` | เสื้อช่วงลำตัว + เข็มขัด/ชายเสื้อ (วาดทับขอบบนของกางเกงเสมอ เพื่อปิดรอยต่อเอว!) |
| **6** | `head_base` + `face` | หัว + ใบหน้า (ยึดตาม `head_anchor`) |
| **7** | `hair_front` | ผมหน้าม้า/ปอยผมข้างแก้ม |
| **8** | `hair_top` หรือ `hat` | ผมด้านบน (ถ้าไม่ใส่หมวกคลุม) หรือ หมวก |
| **9** | `front_arm` + `front_sleeve` | **สำคัญมาก:** แขนข้างใกล้กล้อง + แขนเสื้อ/เกราะไหล่หน้า ต้องวาดทับตัวเสื้อและหัวไหล่ |
| **10 (หน้าสุด)** | `weapon_front` | อาวุธ (เฟรมปกติและเฟรมฟันด้านหน้า) + มือที่กำด้ามจับ |

### เทคนิคที่ 4: การจัดการ "กางเกง & รองเท้า" ในพื้นที่ 8 พิกเซล (Smart Lower-Body System)
เนื่องจากช่วงขาของ Chibi สั้นมาก (~8–9 art px) และถูกชายเสื้อ (`torso_shirt`) คลุมด้านบนไปแล้วครึ่งหนึ่ง:

1. **ให้ขอบล่างของเสื้อ (`torso_shirt`) เป็นตัวปิดรอยต่อเสมอ:**
   - กำหนดเส้นเอวมาตรฐาน (`waist_line`) ในทุกเฟรม
   - เสื้อทุกตัวต้องมีความยาวคลุมลงมาถึงหรือต่ำกว่า `waist_line` อย่างน้อย 1–2 px เพื่อไม่ให้เห็นช่องว่างระหว่างเสื้อกับกางเกงเวลาตัวละครยืดตัวตอนฟัน
2. **กางเกง (`pants`) ใช้ระบบ 4 Archetype Templates + Palette Swap:**
   - แทนที่จะให้ AI วาดกางเกงใหม่ทุกตัว (ซึ่งในพื้นที่ 4×8 px แทบไม่ต่างกันเลยนอกจากสีและขอบขากางเกง) ให้ทำอนิเมชั่นขามาตรฐานไว้ 4 ทรง:
     1. `pants_trousers` (กางเกงขายาวปกติ)
     2. `pants_shorts` (กางเกงขาสั้น เห็นผิวขา)
     3. `pants_greaves` (เกราะขาเหล็ก มีแผ่นสนับเข่า)
     4. `pants_skirt` (กระโปรง/ชายเสื้อคลุมยาว)
   - จากนั้นเปลี่ยนเป็นกางเกงผ้า, กางเกงหนัง, กางเกงเหล็กดำ, กางเกงทอง ได้ไม่จำกัดด้วย `Palette Swap` (3-shade ramp ตามกฎ House Style) โดยไม่เสียค่าเจนและไม่มีวันบั๊ก!

## 5. ประเด็นคำถามเพื่อตัดสินใจร่วมกัน (สำหรับคุยกับ Claude)
1. **จะเริ่มจาก `head_layer.py` (หมวก + ทรงผม) ก่อนไหม?** เพราะทำเหมือน `weapon_layer.py` ได้เลย ไม่ต้องเสีย quota PixelLab แม้แต่ gen เดียว และเห็นผลลัพธ์การแต่งตัวชัดเจนที่สุด (หัวกินพื้นที่ครึ่งตัว)
2. **สำหรับเสื้อและกางเกง:** อยากใช้แนวทาง **(A) เสื้อ+กางเกงแยกด้วย Template ขา + เสื้อจาก PixelLab** หรือ **(B) ระบบ UV Map ที่แปลงภาพนิ่งเสื้อ/กางเกงเป็นอนิเมชั่นทุกท่าด้วยโค้ด**?
