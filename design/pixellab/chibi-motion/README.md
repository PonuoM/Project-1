# Chibi motion: ทดลอง PixelLab แบบ "ออกแบบท่าเองก่อนเจน"

เป้าหมาย (เจ้าของ, 14 ต.ค. 2026): ใช้ PixelLab เป็นหลัก ตัวละครต้นฉบับ (ผมเขียวอมฟ้า chibi) ต้อง
1. ถืออาวุธเปลี่ยนได้อย่างเป็นธรรมชาติ
2. เปลี่ยนเสื้อผ้าได้
3. ท่าใช้สกิลเป็นธรรมชาติ มีน้ำหนัก (ง้าง/ฟาด/ตามแรง) — เอฟเฟกต์สกิลไว้ทีหลัง
ลำดับแรก: การเคลื่อนไหว

อนาคต: Codex ออกแบบชิ้นตัวละคร/ชุด → Claude ต่อ PixelLab ทำภาพและประกอบ

## วิธีการ (pipeline)

```
ref 64px (ตัวต้นแบบ)  ──/estimate-skeleton (0.1 gen)──►  rest skeleton 18 จุด
pose spec (.pose.json) ──chibi_skeleton_pose.py (ฟรี)──►  keypoints + ตัวก้าง preview + GIF ตามจังหวะจริง
                                                          (ตรวจน้ำหนัก/จังหวะก่อนจ่าย)
keypoints + ref        ──/animate-with-skeleton-v3──────►  เฟรมจริง (15 เฟรม = 4 gen)
ref ชุด/อาวุธอื่น      ──/edit-image-pixen (1 gen)──────►  ref ใหม่ท่าเดิม → เจนท่าเดิมด้วย skeleton ชุดเดิม
```

- ท่า = ข้อมูลของเรา (keypoints ต่อเฟรม + ms ต่อเฟรม) ไม่ใช่ของ AI → ท่าเดียวกันใช้ได้กับทุกชุด/อาวุธ
- จังหวะ (ค้างตอนง้าง, เฟรมเร็วตอนฟาด, hit stop) คุมในเกมด้วย ms ต่อเฟรม — AI แค่วาดท่า

คำสั่ง (ไม่มีการเรียก API ยกเว้นบรรทัดที่ส่งงาน):
```powershell
python -I design/tools/chibi_skeleton_pose.py design/pixellab/chibi-motion/heavy-slash.pose.json   # preview ฟรี
python -I design/tools/pixellab_skeleton_payload.py SPEC OUT.json --description "..." --action "..." [--reference other.png]
python -I design/tools/pixellab_client.py animate-with-skeleton-v3 --payload OUT.json --out JOB.json  # จ่าย gen
python -I design/tools/pixellab_wait.py JOB_ID OUTDIR       # poll อย่างเดียว ไม่เจนซ้ำ
python -I design/tools/pixellab_frames_sheet.py SPEC OUTDIR [--skeleton]
```
API key อยู่ใน environment `PIXELLAB_API_KEY` เท่านั้น ห้ามลงไฟล์

## ความรู้ที่ได้ (เก็บไว้ใช้)

| เรื่อง | ข้อเท็จจริง |
|---|---|
| ค่าใช้จ่าย skeleton-v3 | คิดตามเวลา ไม่ขึ้นกับขนาด canvas: 3 เฟรม = 2 gen, 8 = 3, 15 = 4 → ทำคลิปยาวทีเดียวคุ้มสุด |
| estimate-skeleton | 0.1 gen, คืน 18 จุด (x,y เป็นสัดส่วน 0–1 + z_index) |
| edit-image-pixen | 1 gen, รักษาท่า/องค์ประกอบ/สไตล์พิกเซล แก้เฉพาะที่สั่ง → ใช้ทำ ref ชุด/อาวุธใหม่ |
| transfer-outfit-v2 | ย้ายชุดจาก ref ลงแอนิเมชันที่มีอยู่: ≤64px ได้ 15 เฟรม, 65–80px ได้ 8, 81px+ ได้แค่ 3 ต่อครั้ง · ต้อง Tier 1 |
| edit-images-v2 / edit-animation-v2 | แก้ทั้งชุดเฟรมให้สม่ำเสมอ (text หรือ ref) ขีดจำกัดเฟรมเหมือนข้างบน |
| interpolation-v2 | ใส่ 2 keyframe → เติมเฟรมกลาง 4–8 เฟรม |
| บัญชี trial | 40 gen, รันได้ทีละ 1 งาน (ส่งซ้อน = HTTP 429); transfer-outfit-v2 / PixMiniMax / skeleton เวอร์ชันเก่าในเว็บ ต้อง Tier 1 |
| ToS | ไม่มีข้อห้ามหลายบัญชีเขียนไว้ตรงๆ แต่ PixelLab ระงับบัญชีได้ตามดุลยพินิจ (ข้อ 8.1); ภาพที่เจนเป็นของเรา ใช้เชิงพาณิชย์ได้ ห้ามเอาไปเทรนโมเดลอื่น |
| สัดส่วน chibi | หัวสูง ~28px จาก 50px แขนยาวแค่ ~11px → ยกดาบเหนือหัวไม่ได้/ถูกหัวบัง ท่าหนักต้องเหวี่ยงต่ำ/ด้านหน้า ไม่ใช่ฟันจากเหนือหัว |
| มือถือดาบใน ref | estimate บอกว่ามือหน้า (ถือดาบ) คือ LEFT (z ต่ำ = อยู่หลังลำตัว) ต้องให้ทุกเฟรมใช้ข้างเดิม |

**สรุป:** ให้ PixelLab วาด "ร่างกาย+ชุด" (ทำได้ดีและคงที่) แต่ **อาวุธเป็นเลเยอร์แยก** วางที่ตำแหน่งมือ + มุมใบดาบที่เราออกแบบไว้ในทุกเฟรม (`weapon_layer.py`, หมุนแบบ RotSprite) → อาวุธไม่มีวันหาย, เปลี่ยนอาวุธฟรี (ไม่ต้องเจนใหม่), มือที่ถือตรงกับท่าเสมอเพราะท่าออกแบบมาพร้อมอาวุธ

- ข้อจำกัด: ดาบที่หมุนด้วยโค้ดจะหยาบกว่าที่ AI วาดเล็กน้อย ทางแก้ภายหลัง: ทำชุดมุมอาวุธล่วงหน้า (เช่น 16 มุม) แล้วเก็บกวาดมือ

## จากคลิปสอนของ PixelLab (20261014-0706, ทำ VFX)

- **Create image (Pro) ทีละ 16 ชิ้น:** ขนาด 64×64 ได้ตาราง 4×4 = 16 ภาพต่อการเจน 1 ครั้ง (20 gen ≈ 1.25 gen/ชิ้น); 128×128 ได้ 2×2 = 4 ภาพ (20 gen เท่ากัน) · prompt แบบ `Pixel art game VFX, one per frame: Frame 1: ... Frame 2: ...` → ใช้ทำ **สไปรต์อาวุธหลายชิ้นวางแนวนอนเหมือนกันทีเดียว** สำหรับระบบอาวุธเลเยอร์ได้ตรงๆ
- **Animate with text → PixMiniMax (Beta, Tier 1):** เลือกภาพจากตารางเป็น first frame, last frame ไม่บังคับ, คำบรรยายการเคลื่อนไหวสั้นๆ แล้วกดปุ่มขยายคำ (enhance) ให้ AI เขียนละเอียด, จำนวนเฟรม 4–40 (ทีละ 4); 8 เฟรม ≈ 1 gen, 12–16 เฟรม ≈ 2 gen
- เก็บกวาดเฟรมในตัวแก้ไขพิกเซลของ PixelLab (ลบจุดหลุด, เติมสี) ก่อนใช้
- ใช้กับ **เอฟเฟกต์สกิล** (เฟสหลัง) และ trail ของอาวุธ

## จากคลิปของ PixelLab: ชุดแยกชิ้น (20261014-0714, "Building modular clothes")

วิธีทางการของ PixelLab สำหรับ **เสื้อผ้าแยกชิ้นเป็นเลเยอร์** (ตรงกับ brief "ทุกชิ้นแยกชั้น"):
1. ตัวเปล่า (base): หัวโล้น กางเกงในอย่างเดียว ไม่มีเส้นขอบ แรเงาเรียบ + แอนิเมชัน (เช่น เดิน)
2. **Transfer outfit to animation (Pro)**: ภาพเสื้อผ้า "ชิ้นเดียวลอยๆ" (ไม่ต้องสวมบนตัว, ≤128×128) → สวมให้ทุกเฟรมของแอนิเมชัน · ในปลั๊กอินแจ้ง 40 gen ต่อครั้ง
3. **Edit animation (Pro)**: สั่งลบร่างกายออก เหลือแต่เสื้อผ้า (ช่องตัว/แขน/หัวต้องเป็นรูโปร่งใสจริง ไม่ใช่ผิว ไม่ใช่หุ่น) → ได้เลเยอร์เสื้อผ้าที่ขยับตรงกับตัวเปล่าทุกเฟรม · 40 gen ต่อครั้ง
4. ซ้อนเลเยอร์เสื้อผ้าบนตัวเปล่า → ผสมชิ้นได้อิสระ ไม่ต้องเจนใหม่ต่อชุดผสม

คำสั่งลบตัว (เขียนใหม่ด้วยคำของเรา ความหมายเดียวกับในคลิป):
> Erase the character's body completely and keep only the clothing, as if worn by an invisible person. The torso, both arms and the head must become fully transparent holes in the exact places they occupy — no skin, no stumps, no mannequin, no silhouette, no shading inside. Only clothing pixels remain, surrounding empty space.

เข้ากับ pipeline เรา:
- ตัวเปล่า = คลิปร่างกายจาก skeleton-v3 (มือเปล่า), อาวุธ = เลเยอร์ของเรา, เสื้อผ้า = เลเยอร์จาก transfer + edit
- ภาพเสื้อผ้าชิ้นเดียวลอยๆ = งานที่ Codex ออกแบบได้ แล้ว Claude ส่งเข้า PixelLab (ตรงกับแผนเจ้าของ)
- ร่างกายมือเปล่าทุกคลิปอยู่ในกรอบ 53×51px → ครอปเป็น 64×64 ได้ → transfer/edit ได้ครั้งละ 15 เฟรม (ที่ 80px ได้แค่ 8)
- ต้อง Tier 1 ขึ้นไป · ต้นทุนต่อชิ้นต่อท่า ≈ 80 gen (transfer 40 + edit 40) หรือ ≈ 40 ถ้าแยกเสื้อผ้าด้วยการเทียบพิกเซลกับตัวเปล่าเองได้ (ต้องทดสอบ) — แพงกว่าแบบชุดเซ็ต (≈4 gen/ท่า) มาก ควรทดลอง 1 ชิ้น × 1 ท่าผ่าน API ก่อนตัดสินใจ

## MiniMax (M Plan ของเจ้าของ) — วิดีโอ → พิกเซล

- key แบบ Subscription (`sk-cp-…`) ใช้ได้: วิดีโอ H3, ภาพ image-01, เพลง/เสียง, ข้อความ M3.1 · ตรวจโควต้า: `python -I design/tools/minimax_video.py quota` (ไม่เสียโควต้า)
- โควต้าวิดีโอฟรีของเจ้าของ: **Hailuo 2.3 3 คลิป/วัน** (ตัวนับ "video" ใน quota) — H3 คิดเงินแยก (ดูค่าใช้จ่ายจริงด้านล่าง)
- M Plan ออกแบบมาเพื่อใช้ส่วนตัวแบบโต้ตอบ งานผลิตจำนวนมาก MiniMax แนะนำแบบจ่ายตามใช้
- ขั้นตอน: sprite ×8 บนพื้นเทาเรียบ 1280×720 เป็น **ทั้งเฟรมแรกและเฟรมสุดท้าย** (ท่าจบกลับท่าเริ่ม วนลูปได้) → `minimax_video.py create/wait` → `video_to_sprite.py` (ตัดพื้น, ย่อกลับกริดพิกเซล, ล็อกพาเลตต์ของ ref) → เลือกเฟรม + ตั้ง ms เอง
- ระวัง: วิดีโอที่ได้ถูกยืดคนละแกน (1280×720 → 1344×768 = ×1.05, ×1.067) เครื่องมือคำนวณแยกแกนแล้ว
- ผลรอบแรก (mm-chop, 168 วินาที, 1 คลิป): **ดีเกินคาด** ตัวละคร/ชุด/พาเลตต์คงเดิม ดาบอยู่ในมือทุกเฟรม ยกดาบหลังหัวแล้วใบดาบพ้นหัวเอง ตัวบิดตอนง้าง มีเส้นวาดแรง (smear) เอง พุ่งฟันแล้วถอยกลับ · ข้อจำกัด: ดาบวาดรวมในตัว (เปลี่ยนอาวุธต้องเจนใหม่), คุมท่า/จังหวะเป๊ะไม่ได้ (เลือกเฟรมทีหลังแทน), ช่วงค้างในวิดีโอยาวเกิน (ตัดออกตอนเลือกเฟรม)

## ค่าใช้จ่ายสำหรับเกมจริง (ประมาณการ)

ต่อ 1 ชุด (outfit set): ref ใหม่ 1 gen + ร่างกายทุกท่า เช่น ยืน 8 (3) + เดิน 8 (3) + โจมตี 15 (4) + สกิล 15 (4) + โดนตี 3 (2) + ตาย 8 (3) ≈ **20 gen**
- อาวุธ: สไปรต์ละ ~1 gen (pixen) แล้วใช้ได้กับทุกชุดทุกท่า (เลเยอร์)
- หมวก: ทำเป็นเลเยอร์ยึดหัวแบบเดียวกับอาวุธได้ (หัว chibi แทบไม่บิดรูป) → ไม่ต้องเจนใหม่ต่อชุด
- เสื้อ/กางเกง/รองเท้าแยกชิ้นอิสระ = จำนวนชุดผสมระเบิด (เช่น 10×10×10 = 1,000 ชุด × 20 gen) → แนะนำ "ชุดเป็นเซ็ต" + เปลี่ยนสีด้วย palette swap (ฟรี)
- Tier 1 เปิด transfer-outfit-v2 (ย้ายชุดลงแอนิเมชันเดิม เฟรมตรงเป๊ะ) ควรทดสอบเทียบเมื่อสมัครจริง
